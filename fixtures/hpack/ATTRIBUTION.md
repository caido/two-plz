# HPACK fixture provenance

These four JSON stories are adapted from RFC 7541, *HPACK: Header Compression
for HTTP/2*, Roberto Peon and Herve Ruellan, May 2015, Appendix C.3–C.6.
The fixed RFC number/date pins the source; this is not a moving repository corpus.

Primary source (A1, official RFC Editor, tier 1):
https://www.rfc-editor.org/rfc/rfc7541.txt
Sections C.3.1–C.6.3 contain the wire bytes and decoded header lists.
Copyright notice and licensing terms are in the RFC's opening pages.

Legal provisions (A2, official IETF Trust, tier 1):
https://trustee.ietf.org/documents/trust-legal-provisions/tlp-5/
Sections 4.c–4.e, effective March 25, 2015. The RFC requests the Simplified BSD
text for extracted Code Components; that text is included in LICENSE.txt.

Adaptation: remove spaces and ASCII columns from published hex dumps; preserve
header-list ordering; represent each header as a single-entry JSON object;
number cases 0–2; specify initial table capacity (4096 for requests, 256 for
responses). Do not prepend table-size update bytes to the RFC examples. Each
story starts with a fresh decoder and retains state across its three cases.
No bytes are generated by this implementation's encoder.

The separate raw-octet Rust test is project-authored from the representation
rules in RFC 7541 sections 6.1 and 6.2.1, not copied from an external corpus.
It deliberately lives outside JSON's Unicode string representation.

Scope: four stories, twelve cases, no downloads at test time. This is a bounded
independent oracle, not the full historical third-party interoperability corpus.
Encoder round trips are additional checks, not independent wire-byte oracles.
Internal dynamic-table consistency checking is owned separately.
